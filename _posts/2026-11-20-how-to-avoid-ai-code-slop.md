# 가장 신경써줘야 하는 순서
1. 코드베이스에 안티패턴이 없게 만들기. 주석은 낡게 되고 AI가 변명을 작성하는 수단으로 사용되기 때문에 적지 않는다.
2. AI가 실수하는 것들을 글로 지시하지 않고 린트와 테스트로 만든다.
3. 검증에 가장 많은 토큰을 태운다. 과거에는 비효율적이기 때문에 수행할 수 없었던 검증 방법들을 이제 AI로 모두 적용할 수 있게 됐다.
4. AGENTS.md와 rule 같은 산문 형식의 지침.
5. 사람의 검토.

# 자세한 내용

### 1. 코드베이스에 안티패턴이 없게 만들기
AI가 가장 많이 읽는 것은 AGENTS.md도, rules도, 프로젝트에 대한 설명도 아니다. 바로 코드다.
이 코드 자체가 알맞은 아키텍처로, 안티패턴 없이 구성되어야 AI Slop이 생기지 않는다.
useEffect와 같이 적절히 사용하는 방법이 매우 어려운 도구는 아예 사용하지 않는 방식으로 구현한다.
주석은 작성 안 한다. 주석은 과거에 머물러있는 경우가 많고 AI Slop으로 만들어진 주석은 사람이 잘 읽지도 
않는다. AI가 변명을 늘어놓는 수단으로 사용되기도 한다.


### 2. AI가 실수하는 것들을 글로 지시하지 않고 결정론적 검사로 만든다
줄글로 작성해서 AI가 따르게 하려고 하지 말고 lint, test, type 검사를 통해 반복되는 실수를 바로잡는다.
줄글로 지시하면 AI가 따를지 말지 상황에 따라 달라질 수 있지만 결정론적 검사는 통과와 실패 중 하나만 나오기에 결과가 동일하다.

예시: useEffect 사용 금지
```js
// eslint.config.js
rules: {
  "no-restricted-imports": ["error", {
    paths: [{
      name: "react",
      importNames: ["useEffect"],
      message: "useEffect 대신 Dune의 데이터 API를 쓰세요. 근본 원인을 고치세요.",
    }],
  }],
}
```
AI가 useEffect를 쓰면 lint가 실패하고 message를 읽고 수정할 수 있다.

### 3. 검증에 가장 많은 토큰을 태운다
과거에는 비효율적이기 때문에 수행할 수 없었던 검증 방법들을 이제 AI로 모두 적용할 수 있게 됐다.
AI가 검증을 위해 테스트, 린트도 돌리고 사람이 사용하는 디버깅 툴도 사용하도록 한다.
예를 들면 크롬 Dev Tool 같은 것 말이다.

### 4. AGENTS.md, Rule, Skill 같은 산문 형식의 지침
산문 형식의 지침은 핵심적인 지식을 AI에게 전달할 때 사용한다. 판단에 필요한 걸 조금 추가하는 정도이다.

### 5. 사람의 검토
위 내용을 잘 지키면 사람이 검토할 것이 획기적으로 줄어든다. AI가 자체적으로 만든 PR을 다 적용할 만하다.
소프트웨어 배포 주기가 매우 빨라지고 마치 실시간으로 살아서 움직이는 생물 같다.
